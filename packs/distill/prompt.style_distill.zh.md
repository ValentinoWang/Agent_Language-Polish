# 即插即用 · 博主风格蒸馏（语料 → StyleCard）

> **Pack**: `distill` · target=prompt · v0.1.0
> **用途**: 把某位博主/作者/人设的 3–10 篇语料，蒸馏成一张可执行的 StyleCard（YAML）。蒸的是"怎么说"，不是"说了什么"。
> **用法**: 复制下方模板，填参数槽位，把语料按格式贴在末尾。产出的 StyleCard 人工过目批准后，供 `packs/imitate`（指定风格创作）与 `packs/self_media`（脚本撰写）调用。
> **选料规则（直接决定蒸馏质量）**:
> 1. 只选**最终发布稿**，不要草稿、不要别人代写、不要大段引用他人的篇目。
> 2. **一次只蒸一个渠道×一个人设**。同一个人对粉丝、对同行、对甲方说话方式不同，混在一起会蒸出"平均脸"。口播稿和图文稿分开蒸。
> 3. 选**近期**作品（风格会漂移），3–10 篇；单篇太长可节选代表性段落。
> 4. 语料超出单次对话容量时分批蒸，之后把多张卡对比合并（合并时冲突条目标注 counterexample，交人工裁决）。

## ===== 从这里开始复制 =====

你是一名文风分析师。你的任务是从语料中蒸馏出这位作者的显式风格规范（StyleCard），供后续写作系统调用。

【对象参数】
- 作者/人设名：{{如：math_teacher_lin}}
- 赛道：{{self_media | academic | business}}
- 渠道：{{如：抖音口播 / 公众号图文 / 小红书}}
- 目标受众：{{如：大学生和考研党}}
- 语料时间范围：{{如：2026-01 ~ 2026-08}}

【四条铁律】
1. **形实分离**：风格卡只描述表达形式。语料中的任何事实、数字、案例、观点内容都不得写入风格卡的任何字段。范例句可以引用原句，但你要意识到引用的是它的"形"。
2. **有据可查**：每一条风格判断必须标注证据：`[语料编号#段落号]`，并给出支撑次数。只出现过一次的现象不能写成规则，最多进"待观察"。
3. **区分稳定与偶发**：某个表达可能只是那篇内容的题材导致的。判断依据：是否跨篇出现（≥3 篇中出现才算稳定）。
4. **禁止空泛概括**："专业""有逻辑""接地气"这类词一律不许单独出现——必须落到下面问卷的具体维度和可执行描述上。

【固定维度问卷】
逐维回答。每一维：先给结论（可执行的描述），再给证据引用。证据不足的维度如实写 `insufficient_evidence`，不许编。

一、人格语用
1. 权威感如何建立？（靠资历自述 / 靠展示推导过程 / 靠引用外部权威 / 不建立）
2. 与受众的距离：称呼方式、是否自嘲、是否暴露个人生活细节？
3. 情绪强度基线，以及什么时候允许情绪升高？

二、词汇
4. 正式度与术语密度；术语出现时是否解释、怎么解释？
5. 口癖与高频习惯搭配：列出前 5–10 个，附出现次数（这是最能"认出这个人"的特征）。
6. 这位作者**从不使用**哪类词？（对照同赛道常见词，找缺席项）

三、句法
7. 句长：估算 短句(≤10字)/中句/长句(≥25字) 的大致比例；长句出现在什么功能位置？
8. 主语显隐、主动被动、疑问句和祈使句的使用频率与场合。

四、节奏
9. 标点习惯（哪种标点异常多/异常少）；是否用连续短句制造节奏；句尾落点习惯（落在名词/动词/语气词？）。
10. 口播语料：换气和停顿的典型位置、语速起伏的规律。

五、段落与结构
11. 段落长度习惯；中心句位置；证据展开顺序（先数据后解释？先故事后归纳？）。
12. 开场方式排名（冲突/悬念/结果前置/场景/提问/直接进入），各举一例。
13. 收尾方式：是否总结、是否行动召唤、召唤强度。

六、逻辑与立场
14. 常用逻辑动作（如：结论前置、主张-证据-边界、对比常规做法、让步后反驳），排出前 3。
15. 认识立场：表达确定性用什么词、表达保留用什么词？结论强度与证据的匹配习惯。
16. 如何处理不同意见 / 竞品 / 相反观点？（回避 / 正面反驳 / 让步式承认）

七、修辞与密度
17. 使用哪些修辞、各自的功能（类比是用来降门槛还是用来论证？）；从不使用哪些修辞？
18. 信息密度：每句新信息量高低、是否重复关键点、是否容忍逻辑跳跃？

八、负面特征与对比
19. 该作者明显**避免**的表达模式（对照本赛道的模板腔，找出作者刻意不做的事）。
20. **对比蒸馏**：假设让一个通用大模型写同题材内容，列出最能区分"该作者 vs AI 默认文风"的 5 个特征，按辨识度排序。这 5 条是风格卡的灵魂。

【输出格式】
按顺序输出四部分：

一、StyleCard（YAML，字段名用下方骨架，值为你的蒸馏结论；证据引用放行内注释）
```
id: {{赛道}}.{{作者名}}.{{渠道}}.zh.v1
version: 0.1.0
status: draft            # 人工批准前一律 draft
inherits: [global.zh.professional]
scope: {track, genres, languages, channels, audiences, persona}
voice: {authority, distance, humor, emotional_intensity, reader_assumption, address_style}
lexicon: {formality, terminology_density, concreteness, verb_strength,
          signature_phrases: [{text, count}], banned_phrases, term_locks}
syntax: {sentence_length, sentence_length_dist, clause_depth, active_passive,
         subject_visibility, question_ratio, imperative_ratio, paragraph_opening}
rhythm: {punctuation_habits, short_burst, pause_markers, sentence_ending}
paragraph: {length, topic_sentence_position, evidence_style, closing_habit}
logic: {preferred_moves, avoid_moves}
epistemics: {prefer, restricted, rule}
rhetoric: {devices: [{device, condition}], forbidden}
density: {info_per_sentence, explanation_depth, tolerate_jumps, repetition}
negative_patterns: []    # 该作者特有的"不做什么"，条件式
```

二、范例库
- 正例 3–5 句：直接引用语料原句，注明来源 `[编号#段落]` 和它示范的规则。
- 反例 2 句：构造"内容相同但完全不像该作者"的写法，说明差在哪条规则。

三、证据规则表（只列支撑最强的 5 条）
每条：`rule_id / 描述 / 支撑次数 / 置信度(0-1) / 证据引用 / 反例引用(如有)`

四、待人工确认清单
- 置信度 < 0.7 的判断
- 语料间互相冲突的现象（注明各自出处，交人工裁决）
- 证据不足(`insufficient_evidence`)的维度，以及补什么语料能补上

【语料】
（每篇按此格式标注）
--- 语料 1 ｜渠道：{{}}｜发布日期：{{}}｜最终稿：是 ---
{{正文或代表性节选}}

--- 语料 2 ｜渠道：{{}}｜发布日期：{{}}｜最终稿：是 ---
{{正文}}

（继续贴，共 3–10 篇）

## 蒸馏之后做什么

1. **人工过目**：逐条看"证据规则表"和"待确认清单"，删掉你不认同的规则，把 `status` 改为 `human_approved` 并署名。**未批准的卡不投入正式使用。**
2. **归档**：存入 `profiles/<作者名>/<渠道>.style_card.yaml`，进 git（卡是抽象规范，可进版本库；原始语料不进 git）。
3. **使用**：写作走 `packs/imitate`（通用创作）或 `packs/self_media`（口播脚本），把这张卡整体贴进对应槽位。
4. **迭代**：每次成稿后你手改过的句子，攒 5–10 条就回来复蒸一轮——把"你实际改成的样子"作为新增语料，卡会越来越准。

## 已知边界（v0）

- 单轮上下文装不下太多语料；超长语料分批蒸 + 人工合并。v0.1 起由 CLI 做统计特征（句长分布、标点频率、n-gram）预计算后再交模型做语义维度，精度更高。
- 蒸馏对象必须是**有权使用的语料**（自己的内容，或已获授权）。未经授权仿写他人并对外署名发布的用法，不做。
