# StyleOS 开发计划 v0 → v0.3

> 定位：**执行层任务书**。给写代码的人（或 Agent 会话）直接领任务用——每个工作项有编号、交付物和验收条件。
> 设计决策与论证见 [`00_方案总览.md`](00_方案总览.md)，复用来源与坑位见 [`02_openclaw_media_复用清单.md`](02_openclaw_media_复用清单.md)。
> 更新纪律：本文档是进度事实源。完成一个工作项就把状态从 `[ ]` 改 `[x]` 并附提交号；范围变更先改本文档再动代码。

## 0. 阶段总览

| 阶段 | 一句话目标 | 关键交付 | 退出条件 | 触发方式 |
| --- | --- | --- | --- | --- |
| **v0** 即插即用包 | 零基础设施可用 | 4 个 usable Pack + 3 Schema + 方案 | 4 个 Pack 的 DoD 全绿（含盲测） | 已交付，收尾进行中 |
| **v0.1** 文风编译器 | 校验进代码，形态进 git | `styleos` CLI + pack build 编译器 + academic/business 包 | `uv tool install` 后 rewrite 全流程产出三件套；锁定项校验 100% 程序化 | v0 收尾完成后启动 |
| **v0.2** 服务端与 MCP | 多终端、多媒体、可编排 | FastAPI + Qdrant 检索 + MCP server + Mac 采集器 | MCP 工具在 Claude Code 可用且背后走完整 DAG | v0.1 退出后启动 |

三条贯穿所有阶段的红线（详见 00 §1.2 与 §6）：源唯一、规则双投影、形实分离。任何工作项与红线冲突时，红线赢。

## 2. v0.1 —— 文风编译器

### 2.1 先锁定的工程决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| Python / 包管理 | 3.12 + uv（单 pyproject，`uv tool install styleos`） | 原方案既定；多 Mac 终端统一入口 |
| 数据模型 | pydantic **v2 原生 API** | openclaw-media 的 v1 兼容层写法明确不抄（02 §4.3） |
| YAML | pyyaml | 不抄 30 行手写解析器（02 §4.2） |
| CLI 框架 | Typer | 新代码无 argparse 迁移负担；那边的 `--no-write/--dry-run/--smoke` 三档降级与 `--tenant-id` 隔离作为**概念**移植 |
| LLM 层 | 自建薄封装：Anthropic + OpenAI 兼容两个 transport | 参照 `llm_client.py` 的 `generate_json + 校验失败带错误重试` 模式；那边无 Claude transport |
| 存储 | 本地文件 vault（media_vault 模式，路径参数化）+ SQLite 元数据 | v0.1 单机；v0.2 平滑迁 PG/COS |
| 编排 | 普通 Python DAG + 阶段落盘断点续跑 | 参照 viral_content runner；LangGraph 留给 v0.3 审批流 |

### 2.2 工作分解

依赖顺序自上而下；S/M/L 是相对规模。

- [ ] **W1-1 仓库骨架**（S）：`styleos/`（core / adapters / apps / schemas / tests），pyproject，CI（pytest + ruff），`styleos doctor`。验收：CI 绿，`uv tool install` 本地可装。
- [ ] **W1-2 Schema → 代码**（M）：三个 YAML 契约转 pydantic v2 模型；`styleos pack lint` 校验全部 pack.yaml。验收：现有 6 个 pack.yaml 全过 lint；schema 往返测试（load→dump→load 等价）。
- [ ] **W1-3 统计特征提取器**（M）：纯函数模块——句长分布（p25/p50/p75）、段长、标点频率、连接词/情态词、高频 n-gram、口癖计数、问句/祈使句比例。验收：固定语料的特征快照测试；零 LLM 依赖。
- [ ] **W1-4 内容账本节点**（L）：抽取器（LLM + 校验契约，参照 `LLMValidationContract` 注册表模式）+ **回归校验器**（代码级：数字/单位/实体/引用/公式的子串与结构核对，参照 `validate_version_text`）。验收：构造 20 个篡改样本（改数字、删限制条件、抬强度词），召回 100%。
- [ ] **W1-5 负面规则引擎**（M）：解析 `deai.negative.zh.yaml` → ① prompt 注入片段生成器 ② 代码扫描器，同一源双投影。验收：两个投影的规则集合一致性测试；每条关键约束句有"构建出的 prompt 确实包含它"的断言（02 §5.2 的教训）。
- [ ] **W1-6 pack build 编译器**（L）：七组块拼装 → `--target prompt`（再生成现有模板，与手工版 diff 人工审查一次后以编译产物为准）与 `--target skill`（生成 `.claude/skills/<pack>/SKILL.md`）。验收：CI 检查编译产物与源无 drift（重编译 diff 为空）。
- [ ] **W1-7 rewrite 流水线**（L）：确定性 DAG——classify → ledger → style bundle → 段落改写 → 句子润色 → fidelity/style/domain 三审 → bounded repair（≤2 轮）→ 导出 `final.md + diff.md + audit.json`。每节点落盘 JSON，支持 `--resume`。验收：端到端跑通三赛道各一篇；audit 记录卡版本/规则命中/模型配置。
- [ ] **W1-8 distill 流水线**（L）：W1-3 统计特征预计算 + 20 问 LLM 蒸馏（每字段 `{value, evidence, confidence, reason}` 四元组）→ draft 卡；`styleos approve` 人工批准流（候选/确认两段式）。验收：同一语料两次蒸馏的稳定维度一致率 ≥ 80%；卡内零语料事实（人工抽查）。
- [ ] **W1-9 profiles/ 卡库**（M）：StyleCard 版本管理、继承解析器（按 00 §冲突优先级计算 effective card）、同名 id 覆盖语义。验收：多层叠加的冲突解析测试；`styleos profile show --effective`。
- [ ] **W1-10 academic 包 → usable**（M）：`academic_norms`（参照 platform_mechanisms 结构，含学术禁用宣称）、LaTeX 命令与公式锁定、分章节功能规则、diff 交付。验收：Pack DoD 七项 + 泛化门禁（见 §5）。
- [ ] **W1-11 business 包 → usable**（M）：`bp_norms`、陈述定级校验器（定级只降不升）、BP/路演/口播三态。验收：同上；"计划→已实现"篡改样本召回 100%。
- [ ] **W1-12 评测 runner**（S）：硬约束检查程序化 + 盲测记录工具（读写 W0-2 的集子）。验收：`styleos eval run` 输出门线通过/失败报告。

### 2.3 v0.1 退出条件

1. `uv tool install styleos` 后，`styleos rewrite draft.md --profile <卡> --mode conservative` 产出三件套；
2. 锁定项校验 100% 程序化（不再依赖模型自觉）；
3. 6 个 Pack 全部 usable，skill target 已生成并在 ≥2 台终端经 git 同步验证；
4. 编译产物与源零 drift（CI 门禁）；
5. 三赛道盲测对基线偏好率 > 0.6。

## 3. v0.2 —— 服务端、多媒体与 MCP

- [ ] **W2-1 API 与存储升级**（L）：FastAPI（apps/api），SQLite → Postgres 迁移脚本，COS/MinIO 适配器（vault 接口不变）。验收：CLI 可指向远端（`styleos --remote`）。
- [ ] **W2-2 混合检索**（M）：Qdrant dense + sparse + payload 过滤（track/genre/author/channel/quality/time_range）；索引可从主库全量重建。验收：检索返回按 00 配额（结构范例 2–3、句式 3–5、反例 2）；重建脚本幂等。
- [ ] **W2-3 文档语料接入**（M）：Docling（通用）、GROBID（论文）、MarkItDown（轻量）三个 adapter → CanonicalDocument。验收：PDF 论文入库后 segment 带章节角色与页码溯源。
- [ ] **W2-4 音视频接入**（M）：**启动时定一次的决策**——云端部署且接受阿里云依赖 → 复用 openclaw-media `content_flow`（DashScope ASR，含说话人分离）；需要本地/离线 → 自建 yt-dlp + faster-whisper adapter。两条路都收敛到 CanonicalDocument（保留说话人/停顿/口头填充词）。验收：一条真实口播视频完成"下载→转写→蒸馏可用"。
- [ ] **W2-5 MCP server**（M）：apps/mcp 暴露 `style_distill / style_rewrite / style_search / style_profile_get / style_feedback / style_export`；底层写库、删文件、自动批准**不**暴露。验收：Claude Code 挂载后完成一次全流程改写，产物与 CLI 路径一致。
- [ ] **W2-6 反馈闭环**（M）：accept / reject / 手改 diff 写入 Preference Memory；`styleos distill --refresh` 把累计手改并入复蒸。验收：反馈后重蒸的卡出现对应规则变化且带证据。
- [ ] **W2-7 Mac 采集器与同步**（M）：监听目录 → SHA-256 → manifest → 本地解析或上传 → outbox 断网重传；`storage_mode` 三档（local_only / cloud_private / shared_profile）。验收：断网投稿、恢复后自动同步、中央端去重。
- [ ] **W2-8 部署**（S）：Docker Compose（api / worker / postgres / qdrant / grobid）上腾讯云；不上 K8s、不上消息队列（任务表 + 单 worker）。验收：一条命令起全栈 + 冒烟脚本。

**退出条件**：MCP 三个核心工具（distill / rewrite / search）在真实会话可用；两台 Mac + 云端三终端语料同步跑通；原始语料不进 git 的边界经检查脚本守护。

## 4. v0.3 —— 自动优化与高级记忆

**进入条件（数据阈值，全部满足才启动）**：
- 成对偏好样本（accept/reject/手改）≥ 300 条；
- 盲测集每赛道 ≥ 30 题；
- Langfuse 已上线并回填 ≥ 1 个月的运行轨迹（W3-1 因此前置到 v0.2 末尾即可开始）。

- [ ] **W3-1 Langfuse 跟踪**（S）：rewrite/distill 全链路 trace + 盲测结果入库。先于一切优化——没有轨迹就没有优化对象。
- [ ] **W3-2 DSPy 优化层**（L）：把 DAG 各节点 prompt 定义为可优化模块，以成对偏好 + 硬约束通过率为指标；优化只动措辞与组块顺序，**不得**动锁定项与负面规则语义。验收：优化前后在保留盲测集上偏好率提升且硬约束零回退。
- [ ] **W3-3 LangGraph 审批流**（M）：`styleos approve` 迁为可中断恢复的 human-in-the-loop 图；卡批准、偏好升级（一次手改 → 永久规则）都走人工节点。验收：中断后恢复上下文完整。
- [ ] **W3-4 事实层图检索**（L）：GraphRAG 或 HippoRAG 仅接 Evidence Memory（跨论文/市场报告多跳检索）；**风格层继续不用图**。验收：索引可重建，不成为真源。
- [ ] **W3-5 轻量微调评估**（可选，L）：仅当成对数据 ≥ 2000 条且 DSPy 收益进入平台期才立项；先做离线评测卡点，不直接上生产。

**退出条件**：每个产出可回溯（卡版本 / 范例来源 / 模型配置 / trace id）；优化循环"反馈 → 重蒸/重优化 → 盲测"每月可跑一轮。

## 5. 横切纪律（所有阶段生效）

**测试**
- 每条关键 prompt 约束句必须有"构建产物包含它"的断言；
- 负面规则双投影（prompt 注入 vs 代码扫描）集合一致性测试进 CI；
- 篡改样本回归集（改数字/删条件/抬强度/换引用）随账本校验器共同演进。

**泛化门禁**（新增赛道 Pack 的额外验收，规范见 00 §2.4）
- 边际成本 ≤ 一个 pack.yaml + 一个 prompt 模板 + 一份领域禁用宣称清单，`schemas/` 与 `packs/global/` 零修改；
- 引用规则中第 0/1 层占比 > 0.6；
- 新作者建卡：语料齐备后一轮蒸馏出 draft。
违反任何一条 → 先修分层，再上赛道。

**版本与分支**
- `main` 只进已验收工作；开发走 feature 分支，合并即代表通过该项验收条件；
- Pack 与 StyleCard 均 semver：prompt 实质变化升 minor，规则语义变化升 major 并过盲测回归；
- 阶段完成打 tag（`v0.1.0` …）。

**数据与授权红线**
- 原始语料、私密对话、视频不进 git（检查脚本守护）；StyleCard、配置、评测集进 git；
- 蒸馏对象必须有权使用；未经授权仿写他人并对外署名发布的用法不做；
- AI 检测器分数只做观察项，任何阶段不得成为优化目标。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型遵循度差异（v0 纯 prompt 期） | 锁定项偶发漂移 | v0 用"账本先行 + 输出内自检"缓解；W1-4 落地后风险消除 |
| openclaw-media 契约仓外绝对路径 | 复用模块直接跑不起来 | 所有移植先参数化路径（02 §4.1），进 adapter 层不进 core |
| DashScope vs faster-whisper 悬而不决 | W2-4 卡住 | 决策点固定在 v0.2 启动会，按部署环境二选一，两路接口已统一为 CanonicalDocument |
| 中文规则被直译到英文 | 英文产出去 AI 味失效 | 英文另建 `deai.negative.en.yaml` 分身（第 1 层按语言扩展，第 0 层不动） |
| 范围蔓延（前端/图谱/微调提前） | v0.1 交付延期 | 00 §"当前阶段明确不做什么"清单是否决依据；v0.3 全部数据阈值触发 |
| 盲测集被优化污染 | 偏好率虚高 | 保留集不参与 DSPy 训练；每季度换一批保留题 |
