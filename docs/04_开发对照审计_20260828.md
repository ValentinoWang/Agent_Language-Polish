## 4. 发现的偏差与缺陷（按优先级）

### P0（本轮已修复）｜CI 不是 local CI
`.github/workflows/ci.yml` 原为 `on: push/pull_request` + 每次 docker build。账户无 Actions 分钟数时，门禁要么排队要么静默失效，且本地没有等价的一键入口。**修复见 §5。**

### P1-a｜规则卡迁移丢词（源回归，有实测假阴性）
规则卡重构为四级检测器结构是进步，但迁移时**丢失了一批已并入的词条**，与 `docs/02` "openclaw-media 18 条禁语已全部并入"的声明冲突。实测：冒烟输出含"总而言之"，`empty_transition` 却报 `clear`。丢失清单（原卡有、现卡无）：

```text
总而言之 / 不仅如此 / 不难发现 / 让我们(一起) / 赋能 / 打造闭环 / 深度融合 / 引发了广泛关注
```

其中前四个属于 deterministic 可检测词，应回补进对应规则的 `detector.patterns`；后四个原属 `abstract_noun_inflation`/`ai_pet_phrases`，可回补为 statistical `cap` 检测。**修法**：回补 patterns + 增加一个"卡内容回归测试"（断言 docs/02 声明吸收的 18 条在卡中均有归属），防止下次重构再丢。

### P1-b｜deterministic 检测 pattern 过窄
- `mechanical_enumeration` 正则要求 `首先…其次…(再次|最后)` 全链；"首先…其次…"后接"总而言之"即漏检（冒烟已复现）。应放宽为 `首先.{0,120}其次`，全链作为加重项；
- `empty_opening` 的 `近年来越来越多的人` 缺逗号变体（原文常见"近年来，越来越多"）。
**修法**：pattern 放宽 + 用 §4-1a 的回归测试锚住；这类规则的验收应以"原卡 examples_bad 全部命中"为最低线。

### P2-a｜离线 writer 会产生破句，且语义审计放行
冒烟中 conservative 模式把"其次，这不仅是数字的提升，更是价值的体现。"改成"其次，价值的体现。"——短语删除后不做语法闭合，产生病句；语义锚相似度 0.60 > 0.35 阈值，verdict 仍 `passed`。离线基线保守是设计意图，但**condition/claim 类锁应更严**。**修法**：双阈值（<0.35 uncertain；0.35–0.70 降为 `review_required`）；或删除类操作后跑一次句法完整性检查（句子必须含谓词成分）。

### P2-b｜prompt target 与规则卡漂移（"改源不改产物"缺一条腿）
`pack build` 只编译 skill target，且 SKILL.md 内嵌的是 v0 手工 prompt（内嵌规则摘要 17 条）；规则卡已是 21 条四级结构。`RuleEngine.project_prompt()` 已经能从卡生成规则段，但没有接进 prompt/skill 编译，旧退出条件"编译产物与源零 drift"对 prompt target 未实现。**修法**：`pack build --target prompt` 用 `project_prompt()` 替换模板中的规则摘要段（模板留锚点注释），CI 加 drift 检查。

### P3（小项）
- prompt 模板头部仍写 `v0.1.0`，`pack.yaml` 已 `0.2.0`（六个 Pack 同）；
- `mcp_server.py` 覆盖率 58%，为全仓最低；
- `readiness` 的 `largest_source_share` 在零样本时报 `1.0`，语义上应为 `null`（零样本时"来源占比"未定义）；
- docker build 原来在每次 CI 里跑，过重（已随 §5 改为可选层 `CI_DOCKER=1`）。

## 5. 本轮修复：local CI 落地

按"CI 要使用 local CI"的要求：

```text
scripts/ci.sh            # 唯一常规门禁：uv sync → ruff → pytest+覆盖率 → pack lint
                         #   → schema export → skill build → uv build
                         # 档位：CI_FAST=1 快速档（pre-push 用）；CI_DOCKER=1 追加镜像构建
scripts/install-hooks.sh # 安装 pre-push 钩子，推送前自动跑快速档
.github/workflows/ci.yml # 降为 workflow_dispatch 手动触发，且复用 scripts/ci.sh
                         # ——不在 push/PR 上消耗分钟数，本地与云端同一套检查
```

已实测 `bash scripts/ci.sh` 全绿（含 wheel 构建）。合并纪律相应更新为：**合并前本地跑 `scripts/ci.sh`，绿了才推**；README 与 docs/03 §E4 已同步改写。
