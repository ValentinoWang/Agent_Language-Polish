## 4. 剩余改进空间（按优先级）

1. **academic / business 的 prompt 过薄（P2）**：目前是 ~870 字节的"执行合同"（硬约束+输出契约齐全、语义正确），但没有四个 v0 模板的完整形态——缺内嵌分步自检、章节功能分治细则、填槽示例、"从这里开始复制"标记。作为 CLI/skill 的执行合同够用；作为**复制即用的 prompt target** 未达其余四包的标准。建议按 `prompt.deai_rewrite.zh.md` 的骨架加厚，并补 examples 实例（当前 `synthetic_smoke.md` 偏形式化）。
2. **`readiness` 零样本语义（P3，首轮遗留未修）**：`largest_source_share` 在零反馈时仍报 `1.0`，应为 `null`/`n/a`——零样本时"来源占比"未定义，报 1.0 会让面板误读为"来源极端集中"。
3. **`mcp_server.py` 覆盖率 58%（P3，首轮遗留未修）**：全仓最低，未随本轮提升；建议补到 ≥75% 门线。
4. **双 pattern 重复计数（新发现，nit）**：`mechanical_enumeration` 的宽链与全链两个 regex 会在全链文本上同时命中，`occurrences` 被重复计数。状态判定只看 >0 不受影响，但计数进了审计报告，建议全链改为宽链的加重标记而非独立 pattern。
5. **主线不变**：工程侧已领先证据侧两个身位。`styleos readiness` 四项门槛仍全部为 0 进展——下一步唯一要紧的事还是用真实授权作者跑闭环（distill → approve → rewrite → feedback），开始积累成对反馈、保留集与轨迹。

## 5. 一句话回答

**是按文档开发的，而且这一轮连"按审计文档修缺陷"也成立**——docs/04 开出的每一条 P1/P2 都被按建议的修法实现并配回归测试锁死，首轮的假阴性用例重跑由 `pass` 变为 `review_required`，证明修复在行为层面真实生效；local CI 保持为唯一常规门禁且新增了 drift 检查。改进空间只剩两个薄模板、两个 P3 遗留和一个计数 nit——以及始终不变的主线：**给系统喂真实数据**。
